In my free time I've written some small self-hosted tools:

* [Nottario](https://github.com/neverbot/nottario), a task, document and architecture store that coding agents talk to over [MCP](https://modelcontextprotocol.io), so several of them working on the same project share the same context instead of each keeping its own.
* [Owl](https://github.com/neverbot/owl), observability sized for one machine: a metrics dashboard whose dashboards are files you write rather than panels you click together, in one static binary and one SQLite file.
* [Maestro](https://github.com/neverbot/maestro), a workspace where game designers and their AI agents build the design of a game together, as a helper for the PhD I am working on.

I also like to mingle with open-source videogame _things_:

* [okinawa](https://github.com/okinawa-dev/okinawa), a 3D engine in C++ on top of OpenGL, written as a library rather than a framework: it draws the world and leaves the game to the application.
* [okinawa.js](https://github.com/okinawa-dev/okinawa.js), its decade-older 2D javascript ancestor, with no runtime dependencies, which powered dozens of mini serious games in the *pixie.es* programming learning platform for kids (later bought by *Sngular* and renamed as *Sngular Kids*), and several serious games created for *UNED's Faculty of Psychology* to be used in academic studies.
* My itch for vintage [online muds](https://en.wikipedia.org/wiki/Multi-user_dungeon) is tickled with the [maldorne](https://maldorne.org/) platform/organization, where I host several vintage [games](https://maldorne.org/games/) and develop my own games and mudlib: [Hexagon](https://github.com/maldorne/hexagon).

All of these, with more info and screenshots, at [neverbot.com](https://neverbot.com).
